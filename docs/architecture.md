# 阶段 A 音频验证程序

当前实现用于验证公开 Core Audio process taps 路线。**尚未进行真实 FaceTime 通话验收**；能够构建、捕获或显示电平，均不代表已经解决通话时媒体被压低的问题。项目声明的最低系统版本为 macOS 14.2，兼容范围仍以实际构建和设备测试为准。

## 分层与数据流

```text
SwiftUI 验证面板 / AppKit 窗口和菜单栏
    → MainActor AudioController
    → 串行 audio-control 队列上的 AudioSession
    → 目标进程白名单的私有 process tap
    → 包含 tap 和当前默认输出的私有聚集设备
    → C AudioDeviceIOProc：增益平滑 → 立体声联动软限幅
    → 默认输出设备
```

`AudioController` 发布界面状态并保存音源身份和增益；恢复设置后仍需手动启动。创建、停止、资源清理和状态读取在串行工作队列上执行。音频回调直接使用 C 状态，不进入 SwiftUI，不分配内存、加锁、写日志或保存音频。音频仅在内存中流转。

程序读取系统默认输出，并将其加入自己的私有聚集设备；不修改系统总音量，也不把聚集设备设成系统默认输出。FaceTime 保持原有播放路径。目标 tap 使用 `mutedWhenTapped`：捕获被读取期间抑制目标进程的直接输出，以避免原声与处理结果叠加；实际恢复行为仍须按验收表实测。

## 音源身份与处理格式

`AudioProcessDiscovery` 从 HAL 音频进程列表取得进程对象、PID 和播放状态。浏览器辅助进程优先依据可执行文件、嵌套应用路径及可解析的父进程链归入宿主应用；不能确认归属时保留为独立进程，不凭 bundle ID 前缀合并。排除本应用、FaceTime 及已列出的系统通话服务，再以选中应用的确切进程对象建立白名单 tap。启动前重新发现进程，运行期间检查辅助进程集合变化。

当前只接受相同采样率的 Float32 PCM，可处理交错或非交错缓冲。tap 为立体声混合，默认输出须为单声道或立体声；单声道输出取左右声道均值。程序不实现独立重采样器，格式不符会停止初始化并清理资源。

阶段 A **拒绝同时包含物理输入通道的默认输出设备**，并校验聚集设备仅有 tap 的两个输入通道，以免读取或转发麦克风。带输入的 USB 接口等设备可能因此被拒绝；蓝牙设备能力可能随通话模式改变，须实测，不能据此承诺 AirPods 兼容。

## 实时处理与监测

- 增益范围为 0–4 倍，参数以无锁原子方式传递，按约 5 ms 时间常数平滑。
- 超过 0.9 的峰值进入软限幅，输出幅值渐近 0.98；左右声道使用相同衰减系数，保持声道比例。高增益仍可能改变音色和动态范围。
- 回调先清空输出并校验缓冲；帧数或布局不符、出现非有限采样值时输出静音，记录错误，控制层随后停止处理。
- 界面电平是最近一次回调的捕获/处理后采样峰值，限幅帧数是累计值；各指标独立原子读取。它们不测量扬声器最终声压，也不能证明输出避开了 FaceTime 的 ducking。

运行时约每 0.25 秒读取设备、格式及回调状态，约每 2 秒重新发现音源进程。默认输出、声道布局或采样率变化时先停止，再尝试重建；音源退出则停止。连续 5 秒没有回调，或连续 15 秒没有有效媒体信号，会自动停止并提示检查播放、权限和来源。电脑睡眠前停止，唤醒后由用户手动启动。

## 资源释放与验证边界

`SessionResources` 记录部分初始化状态。停止时依次尝试停止设备 IO、销毁 IOProc、销毁私有聚集设备、销毁 tap；即使前面的清理失败，也继续尝试释放 tap，以恢复媒体的直接输出。只有确认回调已停止且注销后，才释放 C 上下文。清理失败的句柄保留供重试；不能确认安全时宁可保留上下文，避免仍在执行的回调访问已释放内存。新的启动会先重试清理，未清理完成则拒绝继续。

正常退出调用同步清理；强制终止后的恢复依赖系统对私有资源和 tap 的回收，必须单独实测。真实通话、受保护流媒体、设备切换、权限撤销和异常退出的结果记录在 `validation.md`，未执行的项目保持“未验证”。只有确认通话中媒体可独立调高、通话音量基本不变且原音源可靠恢复，才能认定阶段 A 通过。

接口依据：[Apple：Capturing system audio with Core Audio taps](https://developer.apple.com/documentation/coreaudio/capturing-system-audio-with-core-audio-taps)。
