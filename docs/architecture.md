# Voice Master 1.0.0 架构

Voice Master 是原生 macOS 自用音量工具，使用 SwiftUI、AppKit、公开 Core Audio process taps 及少量 C 实时处理代码。1.0.0 在已有音频链路上提供双栏界面、应用搜索、常用记录和按应用保存音量。最低构建目标为 macOS 14.2，设备兼容性仍以实测记录为准。

## 分层与数据流

```text
SwiftUI MainPanel / AppKit 窗口和菜单栏
    → MainActor AudioController
        → AudioPreferences：本地偏好、按应用增益、搜索记录
        → ApplicationSearch：中文/英文/拼音/首字母过滤
        → 串行 audio-control 队列上的 AudioSession
            → 目标进程白名单的私有 process tap
            → 包含 tap 和当前默认输出的私有聚集设备
            → C AudioDeviceIOProc：增益平滑 → 立体声联动软限幅
            → 默认输出设备
```

音频仅在内存中流转，不保存、不上传。程序读取系统默认输出并加入自己的私有聚集设备，不修改系统总音量或默认设备。FaceTime 保持原有播放路径。

## 界面与控制层

`MainPanel` 左侧呈现音频应用、搜索和常用记录，右侧呈现选中应用、增益、启停和输出状态。可归属的应用直接展示；系统和未归属的音频进程默认折叠，搜索命中时展开。图标由 `ApplicationIconCache` 缓存，诊断信息和链路电平在详情中按需展开。

`AudioController` 隔离于 MainActor，发布应用列表、选择、搜索、音量、状态类型和电平。音频初始化、停止、资源清理及状态读取在同一串行工作队列执行。通过请求代次丢弃过期的启动、停止、轮询和刷新结果；正常退出先使待返回结果失效，再同步清理音频资源。

搜索过滤只改变结果列表，不清除当前选择或修改正在使用的音量。缓存键包含原始查询和完整应用列表，避免仅更新电平时重复执行拼音转写。音源列表的自动刷新约每 2 秒执行一次，运行和空闲时都能更新；成功刷新不覆盖音频错误状态。切换应用会先停止当前处理，再加载目标应用的配置，随后由用户手动开始。

快捷键为 `⌘F` 搜索、`⌘R` 刷新、`⌘0` 恢复 100%、`⌘1` 打开窗口；搜索回车确认首个匹配项，Esc 清空查询。关闭窗口保留菜单栏和处理状态，退出应用则清理资源。

## 搜索与本地偏好

`ApplicationSearch.filter` 按名称、bundle ID、名称的拼音和首字母匹配，忽略大小写、变音符号及宽度差异。多个查询词须全部命中任一可搜索字段；过滤稳定保留发现顺序，不归并音源。拼音使用 Foundation 的 MandarinToLatin 及去音调变换，另保留「音乐」常用读音 `yinyue`，兼容系统转写的 `yinle`。

`AudioPreferences` 在 MainActor 上封装 UserDefaults，使用独立命名空间存储选择、上次增益、查询、应用配置和搜索记录。增益限于 0–4，非有限值回到 1。新应用没有配置时返回 100%，不继承另一个应用的增益；未选择应用时返回上次全局值。

应用配置优先以 bundle ID 标识，没有 bundle ID 时使用稳定的 `app:` 宿主路径。旧版 `gain` 与 `selectedApplicationID` 单次迁移，原键保留；选中应用的路径配置在发现 bundle ID 后提升为 bundle 配置，并消费路径别名，避免同路径的替代应用继承旧增益。独立 `process:PID` 音源不持久化选择或配置，本次运行的临时增益还包含 HAL 进程对象身份，避免编号复用。

搜索输入即时保存到 `lastSearchQuery`，仅在回车确认、选择结果或使用历史快捷项时记录次数。历史查询会 trim、折叠空白，并按大小写及变音符号去重；顺序为固定优先、使用次数、最近使用。最多保存 5 个固定项和 8 个普通项，第 6 个固定项会将最久未使用的固定项降为普通项。清空最近搜索保留固定项，删除操作则可单独移除固定项。重启恢复搜索、稳定的应用选择及增益，不自动开始音频处理。

偏好只包含本地查询、应用身份和增益，不含音频或持久化 PID。损坏或类型不符的数据回退至安全默认值。

## 音源身份与处理格式

`AudioProcessDiscovery` 从 HAL 音频进程列表取得进程对象、PID 和播放状态。浏览器辅助进程优先依据可执行文件、嵌套应用路径及可解析的父进程链归入宿主应用；无法确认归属时保留为独立进程，不按 bundle ID 前缀合并。排除本应用、FaceTime 及已列出的系统通话服务，以选中应用的确切进程对象建立白名单 tap。启动前重新发现进程，运行期间检查辅助进程集合变化。

目标 tap 使用 `mutedWhenTapped`，仅在捕获被读取期间抑制原始直接输出，以避免原声与处理结果叠加。当前只接受同采样率 Float32 PCM，支持交错或非交错缓冲；tap 为立体声混合，默认输出须为单声道或立体声。单声道输出取左右声道均值，不实现独立重采样器，格式不符时停止初始化并清理。

当前主动拒绝同时包含物理输入通道的默认输出设备，并校验私有聚集设备的 tap UID 及两个输入通道，避免读取或转发麦克风。带输入的 USB 接口等设备可能被拒绝；蓝牙能力可能随通话模式改变，不能据此承诺 AirPods 兼容。

## 实时处理与监测

- 增益参数以无锁原子方式传递，按约 5 ms 时间常数平滑；实时回调不进入 SwiftUI、不分配内存、不加锁、不写文件或日志。
- 超过 0.9 的峰值进入软限幅，输出幅值渐近 0.98；左右声道使用相同衰减系数，保持声道比例。高增益仍可能改变音色和动态范围。
- 回调先清空输出并校验缓冲；帧数或布局不符、出现非有限采样时输出静音并记录错误，控制层随后停止。
- 界面电平是最近回调的捕获/处理后采样峰值，限幅帧数是累计值。指标独立原子读取，不代表扬声器最终声压或 FaceTime ducking 的实际补偿效果。

运行时约每 0.25 秒读取设备、格式及回调状态，约每 2 秒重新发现音源进程。默认输出、声道布局或采样率变化时先停止再尝试重建；音源退出则停止。连续 5 秒没有回调或 15 秒没有有效媒体信号时自动停止。电脑睡眠前停止，唤醒后手动开始。

## 资源释放与验证

`SessionResources` 记录部分初始化状态。停止时依次尝试停止设备 IO、销毁 IOProc、销毁私有聚集设备、销毁 tap；前面的清理失败时仍尝试释放 tap，以恢复媒体的直接输出。只有确认回调已注销或设备已销毁，才释放 C 上下文。清理失败的句柄保留供重试，无法确认安全时保留上下文，避免回调访问已释放内存。新启动先重试清理，未完成则拒绝继续。

应用图标和菜单图由可编辑 SVG 生成，正式资源位于 `.app/Contents/Resources`，运行时从 `Bundle.main` 加载。菜单图显式装入 18 px / 36 px 两种表示，统一使用 18 pt 模板尺寸。无需 SwiftPM 资源 bundle 或绝对构建路径回退。

`--render-preview` 使用独立 UserDefaults、示例应用和关闭监测的控制器，离线渲染明暗外观、最小尺寸及空状态；`--diagnose` 仅读元数据；`--smoke-test` 检查真实启动和图标加载。它们不启动音频捕获，不能替代实际控件交互和设备验收。

正式自用版的交付与音频场景逐项验收分别记录。用户已反馈试用暂无问题，但真实 FaceTime、受保护内容、蓝牙、权限撤销、设备切换及异常退出恢复仍须补齐细节，见 `validation.md`；不将界面完成或自动化检查等同于完全解决 FaceTime 自动压低。

接口依据：[Apple：Capturing system audio with Core Audio taps](https://developer.apple.com/documentation/coreaudio/capturing-system-audio-with-core-audio-taps)。
