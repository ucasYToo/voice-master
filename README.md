# Voice Master

原生 macOS 应用独立音量工具，自用版 **1.0.0**。选择一个媒体应用，即可在本机将其音量调至 0–400%，并为每个应用记住上次使用的增益。所有音频在内存中实时处理，不保存、不上传，不修改系统总音量或默认输出设备。

双栏窗口在左侧展示音频应用、搜索及常用记录，右侧提供音量、开始/停止和输出状态。支持中文、英文、完整拼音和首字母搜索；菜单栏可随时重开窗口或停止处理。用户已试用并反馈暂无问题，FaceTime、蓝牙及其他设备的逐项实测记录仍待补齐，见 [验证记录](docs/validation.md)。

## 下载

在 [GitHub Releases](https://github.com/ucasYToo/voice-master/releases) 下载 `VoiceMaster-1.0.0-macOS-arm64.zip`，解压后将 `Voice Master.app` 放入「应用程序」。`SHA256SUMS.txt` 用于校验下载文件。当前仅提供 Apple Silicon 版本，使用 ad hoc 签名、尚未公证；安装和兼容范围见 [1.0.0 发布说明](docs/releases/v1.0.0.md)。

## 构建和打开

需要 macOS、Swift 6 工具链、macOS SDK 和 `codesign`。当前开发环境为 macOS 26.5.2 / Apple Silicon / Swift 6.3.3 / Command Line Tools。构建目标最低版本设为 14.2，其他系统和设备尚未实测。

```sh
./scripts/build-app.sh
open "dist/Voice Master.app"
```

无需完整 Xcode、第三方依赖或服务器。脚本生成本机 ad hoc 签名的 `.app`，尚未配置开发者签名及公证。日常从固定位置的 `.app` 启动；重新打包前退出旧应用，重新构建后 macOS 可能要求再次授权。`swift run` 可用于开发诊断，正式运行和资源加载以打包后的应用为准。

应用和菜单栏采用 D「声线 V」图标，菜单栏使用支持明暗外观及 Retina 的单色模板。正式 SVG 源位于 `Resources/Icons/`，打包时通过系统 `sips` / `iconutil` 生成多尺寸 `.icns` 和菜单栏 1× / 2× PNG。单独更新资源可运行 `./scripts/generate-icons.sh`，随后重新打包。

## 使用

1. 让浏览器或播放器开始播放媒体，打开 Voice Master。首轮建议使用 **MacBook Pro 内建扬声器**。
2. 在左侧选择音源，或搜索应用名称、bundle ID、拼音及首字母，例如「播放器」可输入 `bofangqi` 或 `bfq`。多词查询要求每个词均匹配。Chrome 等能确认宿主的辅助进程会合并，系统与未归属的音频进程放在可展开的「其他音频进程」中。
3. 点击「开启音量调节」。首次使用按系统提示允许录制系统音频；也可在「系统设置 → 隐私与安全性 → 屏幕与系统音频录制」检查授权。名称可能随系统版本变化，若系统要求重启应用，请退出后重新打开。
4. 初次选择一个应用时从 100% 开始，确认没有重复声音，再逐步提高增益。可以拖动滑块，或使用 100%、150%、200% 快捷值；恢复按钮将当前应用设回 100%。接近满幅的信号会进入软限幅，因此 100% 也可能改变高峰值音频的动态。
5. 点击「停止调节」释放捕获，或从菜单栏退出。关闭窗口后应用继续运行，可从菜单栏或 Dock 重新打开。

切换到另一个应用会先停止当前处理，再加载该应用记住的音量，点击「开启音量调节」后生效。重启会恢复上次搜索、可稳定识别的应用选择及增益，由用户手动开始处理。无法确认宿主的独立 PID 音源只保留本次运行的选择及增益，避免进程编号复用。

列表约每 2 秒自动刷新，也可手动刷新。刷新列表不会覆盖音频错误提示；等待中的应用重新出现时会恢复可选状态。搜索只过滤左侧列表，保留当前选择和音量。

## 常用与最近搜索

在搜索框按回车、选择搜索结果，或点击已保存的搜索时，才计入使用记录；每次输入文字只保存当前查询，不增加历史次数。回车会选中首个匹配结果，不会自动开始音频处理。

记录按固定优先、使用次数、最近使用顺序排列。最多保留 **5 个固定搜索和 8 个普通记录**；左侧显示常用快捷项，更多记录可从管理菜单查看。右键记录或使用管理菜单可固定、取消固定及删除；固定第 6 个搜索时，最久未使用的固定项会转为普通记录。「清空最近搜索」保留已固定项。

每个应用的音量优先按 bundle ID 保存，没有 bundle ID 时使用稳定的宿主路径。旧版的全局音量及已选应用会自动迁移到对应应用配置，其他初次使用的应用仍为 100%。

| --- | --- |
| `⌘F` | 聚焦应用搜索 |
| `⌘R` | 刷新音频应用 |

## 设备与音频限制

- 同时处理一个应用，目标音频混成立体声；支持输出专用的单声道/立体声设备和同采样率 Float32 PCM。
- **暂不支持同时含物理输入的默认输出设备**，例如部分 USB 音频接口或蓝牙通话模式。初始化会明确拒绝，AirPods 的兼容性仍待实测。
- 默认输出、采样率或声道变化时先停止再重建，失败则停止。源应用退出后需重新开始处理；辅助进程集合变化会触发重建，可能有短暂间断。
- 连续 5 秒无回调或 15 秒无媒体信号会自动停止。暂停媒体超过 15 秒后需再次点击开始；权限缺失、选错辅助进程或受保护内容也可能造成静音。
- 睡眠时停止，唤醒后手动开始。真实设备断开、权限撤销、强制退出的播放恢复仍需逐项验收。
- FaceTime 及已知系统通话服务不会作为可选捕获源。重新输出的媒体仍可能受到系统 ducking，界面电平不代表最终听感，尚不能宣称完全关闭 FaceTime 的自动压低。
- 受 DRM 保护的流媒体、共享 WebKit 音频进程、多设备场景及其他系统版本的表现，以后续实测为准。

## 开发检查

```sh
./scripts/test.sh
./scripts/check-dsp.sh
"dist/Voice Master.app/Contents/MacOS/VoiceMaster" --diagnose
"dist/Voice Master.app/Contents/MacOS/VoiceMaster" --smoke-test
"dist/Voice Master.app/Contents/MacOS/VoiceMaster" --render-preview dist/ui-preview
```

`test.sh` 使用 Swift Testing，兼容本机 CLT 的额外框架搜索路径。`check-dsp.sh` 运行带 AddressSanitizer 和 UndefinedBehaviorSanitizer 的独立 C 音频检查。`--diagnose` 仅输出设备和进程元数据；`--smoke-test` 打开真实界面约两秒后退出，二者均不开始捕获。

`--render-preview` 用隔离的示例设置离线渲染窗口，覆盖明暗外观、最小尺寸和空状态；不录音、不修改用户的常用配置。离线渲染与生命周期检查不能替代真实控件交互或 FaceTime 验收。当前版本的检查结果由 [验证记录](docs/validation.md) 汇总；音频链路和偏好设计见 [架构文档](docs/architecture.md)，原始需求及后续工作见 [交接文档](HANDOFF.md)。

构建完成后，运行 `./scripts/package-release.sh` 生成 ZIP 与 SHA-256 校验文件，输出到 `dist/releases/v1.0.0/`。脚本仅打包应用和公开安装说明，并检查解压后的签名与可执行权限；不会包含本机诊断或预览文件。
