# Voice Master

原生 macOS 媒体音量验证程序。选择一个媒体应用，在本机捕获其输出，应用 0–400% 增益和软限幅，再播放至系统默认输出设备。提供菜单栏入口、启动/停止、应用刷新和链路电平；保存音源及增益，重启后手动启动。

**当前为阶段 A。用户已试用并反馈暂无问题；真实 FaceTime 通话效果尚缺完整的实测记录，不能宣称已经解决通话造成的媒体音量压低。** 电平表显示处理前后的信号，不代表最终听感。完整实测状态见 [验证记录](docs/validation.md)。

## 构建和打开

需要 macOS、Swift 6 工具链、macOS SDK 和 `codesign`。当前在 macOS 26.5.2 / Apple Silicon / Swift 6.3.3 / Command Line Tools 上构建。构建目标最低版本设为 14.2，其他系统和设备尚未实测。

```sh
./scripts/build-app.sh
open "dist/Voice Master.app"
```

无需完整 Xcode、第三方依赖或服务器。脚本生成本机 ad hoc 签名的 `.app`，不是经过公证的分发包。重新构建后 macOS 可能重新要求授权；日常从固定位置的 `.app` 启动，避免混用 `swift run` 和应用包申请录制权限。重新打包前退出旧应用。

应用图标采用 D「声线 V」，菜单栏使用对应的单色模板图形，适配浅色/深色外观及 Retina。正式 SVG 源位于 `Resources/Icons/`；打包脚本通过系统 `sips` / `iconutil` 生成多尺寸 `.icns` 和菜单栏 1× / 2× PNG。单独更新资源可运行 `./scripts/generate-icons.sh`，随后重新打包。

## 使用

1. 首轮建议使用 **MacBook Pro 内建扬声器**，让浏览器或播放器开始播放媒体。
2. 打开应用，刷新并选择媒体音源；Chrome 等可确认宿主的辅助进程会合并。无法确认归属的辅助进程以独立 PID 显示，需要分别尝试。
3. 点击「启动处理」。首次启动时，按系统提示允许 Voice Master 录制系统音频。也可在「系统设置 → 隐私与安全性 → 屏幕与系统音频录制」检查授权，名称可能随系统版本变化；若系统要求重启应用，请退出后重新打开。
4. 从 100% 开始，确认没有重复声音，再逐步提高增益。超过 0.9 的峰值会进入软限幅，因此 100% 也可能对接近满幅的音频产生影响。
5. 用户自行开始 FaceTime 通话，对比处理停止/开启、双方静默/任一方说话时的媒体及通话音量，保持系统音量和输出设备不变。
6. 点击「停止处理」释放捕获，或从菜单栏退出。关闭窗口后应用继续运行，可从菜单栏或 Dock 重开面板。

音频仅在内存中处理，不保存、不上传。本工具不修改系统音量、不修改系统默认设备；FaceTime 及已知系统通话服务不在可选捕获源中。

## 当前限制

- 只处理一个应用，目标音频混成立体声；支持输出专用的单声道/立体声设备和同采样率 Float32 PCM。
- **暂不支持同时含物理输入的默认输出设备**，例如部分 USB 音频接口或蓝牙通话模式。初始化会明确拒绝；AirPods 尚未实测。
- 默认输出、采样率或声道变化时先停止再重建；失败则停止。源应用退出后需重新启动处理；辅助进程集合变化会触发重建，可能有短暂间断。
- 连续 5 秒无回调或 15 秒无媒体信号会自动停止。暂停媒体超过 15 秒后，需要再次点击启动。静音也可能由权限缺失、辅助进程选错或受保护媒体造成，界面不能据此确定原因。
- 睡眠时停止，唤醒后手动启动。真实设备断开、权限撤销、强制退出的恢复行为仍待验收。
- 受 DRM 保护的流媒体、共享 WebKit 音频进程、动态 ducking 和多设备场景尚未验证；普通测试音频成功不能替代这些测试。

## 检查

```sh
./scripts/test.sh
./scripts/check-dsp.sh
"dist/Voice Master.app/Contents/MacOS/VoiceMaster" --diagnose
"dist/Voice Master.app/Contents/MacOS/VoiceMaster" --smoke-test
```

`test.sh` 使用 Swift Testing，兼容本机 CLT 的额外框架搜索路径。`check-dsp.sh` 运行带 AddressSanitizer 和 UndefinedBehaviorSanitizer 的独立 C 音频检查。`--diagnose` 只输出设备和进程元数据，不请求捕获权限；`--smoke-test` 打开真实界面约两秒后退出，不启动音频处理。

资源清理测试使用模拟的 HAL 结果，不能证明真实异常退出一定恢复播放。路线和实现说明见 [架构文档](docs/architecture.md)，原始目标和验收要求见 [交接文档](HANDOFF.md)。
